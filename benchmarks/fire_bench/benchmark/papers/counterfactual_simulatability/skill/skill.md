## Research Question
Determine whether natural-language explanations generated by a language model improve a separate predictor model’s ability to correctly simulate that model’s outputs on counterfactual NLI and QA inputs, compared with having only the original input and original prediction.

## Dataset & Data Budget
- Exact dataset source:
  - NLI: HuggingFace `nyu-mll/multi_nli` via `from datasets import load_dataset; ds = load_dataset("nyu-mll/multi_nli")`
  - QA: HuggingFace `rajpurkar/squad_v2` via `from datasets import load_dataset; ds = load_dataset("rajpurkar/squad_v2")`
- Recommended sample size for 2-hour budget:
  - NLI: 80 original examples total
  - QA: 80 original examples total
  - Each original example yields 1 counterfactual variant
  - Total original items: 120
  - Total counterfactual items: 120
- Model-role budget:
  - Target models whose behavior is being simulated: `gpt-3.5-turbo` and `gpt-4`
  - Proxy “human simulator” model: use `gpt-3.5-turbo` for all simulation judgments to conserve budget and time
  - Use exactly these model identifiers in code and prompts; do not substitute unsupported variants such as `gpt-4-turbo` or `gpt-4.1` unless the utility explicitly exposes them
- Conservative API budget estimate:
  - With 80 NLI + 80 QA originals = 160 items and one counterfactual each:
    - Per target model: 160 original prediction+explanation calls + 160 counterfactual prediction calls = 320 calls
  - Proxy simulator:
    - 2 target models × 160 items × 2 conditions = 640 simulation judgments
  - Total simulator load remains under 1000 calls/model
  - Do not add reverse base/proxy pairings or extra pilot studies unless they fit the stated budget after accounting for retries
- How to sample:
  - Use `seed = 42`
  - NLI sampling:
    - Use split `validation_matched`
    - Filter out label `-1`
    - Stratified sample 27 entailment, 27 neutral, 26 contradiction for 80 total
  - QA sampling:
    - Use split `validation`
    - Keep only answerable examples: `len(example["answers"]["text"]) > 0`
    - Randomly sample 80 examples
- Train / validation / test split:
  - No training
  - Use all sampled items as evaluation set
  - For robustness, report results separately by task and target model, then macro-average

## Experimental Conditions
1. Target model conditions:
   1. `gpt-3.5-turbo` as target model
   2. `gpt-4` as target model

2. Task conditions:
   1. NLI on MultiNLI
   2. QA on SQuAD v2

3. Simulator-information conditions:
   1. No-explanation baseline:
      - Proxy simulator sees original input and target model’s original prediction only
   2. Explanation condition:
      - Proxy simulator sees original input, target model’s original prediction, and target model’s free-text explanation

4. Counterfactual conditions:
   1. NLI counterfactual:
      - Modify hypothesis by inserting or removing negation, or swapping one key entity/adjective
   2. QA counterfactual:
      - Modify question by replacing one key entity, number, or attribute with a contrasting value drawn from context or a simple semantic alternative

- QA task must remain answer-string prediction as specified below; do not simplify it to answerability-only classification
5. Measured outcomes for every sampled item:
   1. Original target-model prediction
   2. Original target-model explanation
   3. Counterfactual input
   4. Actual target-model prediction on counterfactual
   5. Proxy simulator prediction of target-model counterfactual output without explanation
   6. Proxy simulator prediction of target-model counterfactual output with explanation

6. Required comparisons:
   1. Explanation vs no-explanation within each task × target-model cell
   2. Macro-average across tasks for each target model
   3. Macro-average across both target models
   4. Optional descriptive split by whether the target model changed its answer from original to counterfactual

## Implementation Specification
- Architecture or model name:
  - No local training
  - Target models: `gpt-3.5-turbo`, `gpt-4`
  - Proxy simulator model: `gpt-3.5-turbo`
  - Inference utility: `from utils.llm_inference import LLMInference`
  - Repository-root execution check: scripts must run from repo root or explicitly append the repo root to `sys.path` before importing `utils.llm_inference`
  - Before launching the full run, verify whether `LLMInference` exposes `batch_generate()`; if not, implement a thin batched loop over `generate()` rather than assuming the method exists

- Optimizer / training:
  - None
  - Set global random seed to `42` for Python, NumPy, and dataset sampling

- Batch size / steps:
  - Use `batch_generate()` with batch size `20`
  - Process in this order:
    1. Generate original predictions+explanations for one task × target model at a time
    2. Construct counterfactuals offline
    3. Generate actual target-model counterfactual predictions
    4. Generate simulator judgments for both info conditions

- Exact prompt templates:

  - NLI target-model original prediction + explanation prompt:
    - System: `You are a careful natural language inference system.`
    - User:
      - `Task: Read the premise and hypothesis.`
      - `Return exactly two lines:`
      - `LABEL: <entailment|neutral|contradiction>`
      - `EXPLANATION: <one concise sentence explaining the decision>`
      - `Premise: {premise}`
      - `Hypothesis: {hypothesis}`

  - NLI target-model counterfactual prediction prompt:
    - System: `You are a careful natural language inference system.`
    - User:
      - `Task: Read the premise and hypothesis.`
      - `Return exactly one line:`
      - `LABEL: <entailment|neutral|contradiction>`
      - `Premise: {premise}`
      - `Hypothesis: {counterfactual_hypothesis}`

  - QA target-model original prediction + explanation prompt:
    - System: `You are a careful question answering system.`
    - User:
      - `Answer the question using only the context.`
      - `If the question is unanswerable from the context, output NO_ANSWER.`
      - `Return exactly two lines:`
      - `ANSWER: <short span or NO_ANSWER>`
      - `EXPLANATION: <one concise sentence explaining why>`
      - `Context: {context}`
      - `Question: {question}`

  - QA target-model counterfactual prediction prompt:
    - System: `You are a careful question answering system.`
    - User:
      - `Answer the question using only the context.`
      - `If the question is unanswerable from the context, output NO_ANSWER.`
      - `Return exactly one line:`
      - `ANSWER: <short span or NO_ANSWER>`
      - `Context: {context}`
      - `Question: {counterfactual_question}`

  - NLI simulator prompt, no-explanation baseline:
    - System: `You are simulating another model's behavior. Predict what label that model would output on a modified input.`
    - User:
      - `Original input:`
      - `Premise: {premise}`
      - `Hypothesis: {hypothesis}`
      - `The model's original output was: {orig_label}`
      - `Modified input:`
      - `Premise: {premise}`
      - `Hypothesis: {counterfactual_hypothesis}`
      - `Predict the original model's output on the modified input.`
      - `Return exactly one line:`
      - `LABEL: <entailment|neutral|contradiction>`

  - NLI simulator prompt, explanation condition:
    - Same as above plus:
      - `The model's explanation of its original output was: {explanation}`

  - QA simulator prompt, no-explanation baseline:
    - System: `You are simulating another model's behavior. Predict what answer that model would output on a modified input.`
    - User:
      - `Original input:`
      - `Context: {context}`
      - `Question: {question}`
      - `The model's original output was: {orig_answer}`
      - `Modified input:`
      - `Context: {context}`
      - `Question: {counterfactual_question}`
      - `Predict the original model's output on the modified input.`
      - `Return exactly one line:`
      - `ANSWER: <short span or NO_ANSWER>`

  - QA simulator prompt, explanation condition:
    - Same as above plus:
      - `The model's explanation of its original output was: {explanation}`

- Counterfactual construction rules:
  - NLI:
    - Apply first successful rule in order:
      1. If hypothesis contains `not`, `no`, `never`, remove one negation token
      2. Else insert `not` after first auxiliary verb in hypothesis (`is/are/was/were/has/have/had/can/will/do/does/did`); if none, prepend `It is not true that `
      3. If a named entity token appears, swap first repeated capitalized token with another capitalized token from premise if available
    - Keep only examples where counterfactual hypothesis differs from original string
  - QA:
    - Apply first successful rule in order:
      1. Replace first capitalized entity in question with a different capitalized token from context
      2. Replace one number in question with a different number found in context
      3. Toggle one attribute word from a fixed map:
         - `first↔last`, `largest↔smallest`, `highest↔lowest`, `before↔after`
    - Keep only examples where counterfactual question differs from original string

- Sampling parameters for all model calls:
  - `temperature = 0.0`
  - `top_p = 1.0`
  - `max_tokens = 64`
  - `n = 1`

- Number of samples per condition:
  - Per task × target model:
    - 80 examples
    - 2 simulator conditions
  - Total simulator judgments:
    - 80 × 2 tasks × 2 target models × 2 conditions = 640

- Parsing / normalization:
  - NLI labels must be lowercased and mapped to exactly `{entailment, neutral, contradiction}`
  - QA answers:
    - Lowercase
    - Strip punctuation/articles/extra whitespace using SQuAD-style normalization
    - Treat empty or malformed output as `NO_ANSWER`

- Exact metrics and formulas:
  - Simulatability accuracy for condition `c`:
    - `Acc_c = (1/N) * sum_i 1[sim_pred_i == target_cf_pred_i]`
  - Explanation gain:
    - `Gain = Acc_with_expl - Acc_no_expl`
  - For QA exact match:
    - `EM = (1/N) * sum_i 1[normalize(sim_pred_i) == normalize(target_cf_pred_i)]`
  - For NLI:
    - same exact-match accuracy over 3 labels
  - Secondary “change-only” accuracy:
    - Evaluate only items where `target_cf_pred_i != target_orig_pred_i`
  - Statistical test:
    - Paired binary comparison between explanation and no-explanation on the same items using McNemar’s test
    - For each item define correctness under both conditions relative to actual target counterfactual prediction
    - Use exact McNemar if discordant pairs < 25, otherwise chi-square McNemar
  - Significance threshold:
    - `alpha = 0.05`
  - Multiple comparisons:
    - Holm-Bonferroni over the 4 primary cells:
      - (`gpt-3.5`, NLI), (`gpt-3.5`, QA), (`gpt-4`, NLI), (`gpt-4`, QA)

- File paths:
  - Save sampled data: `artifacts/sampled_nli.jsonl`, `artifacts/sampled_qa.jsonl`
  - Save target-model original outputs: `artifacts/{task}_{target_model}_original.jsonl`
  - Save counterfactual inputs: `artifacts/{task}_counterfactuals.jsonl`
  - Save target-model counterfactual outputs: `artifacts/{task}_{target_model}_counterfactual.jsonl`

## Evaluation Protocol
- Primary metric:
  - Counterfactual simulatability accuracy:
    - NLI: exact label match between simulator prediction and target model’s actual counterfactual label
    - QA: exact normalized answer match between simulator prediction and target model’s actual counterfactual answer
- Secondary metrics:
  - Explanation gain `Acc_with_expl - Acc_no_expl`
  - Change-only accuracy on subset where target model changed output under counterfactual
  - Rate of target-model output change under counterfactual:
    - `ChangeRate = (1/N) * sum_i 1[target_cf_pred_i != target_orig_pred_i]`
  - For QA only:
    - `NO_ANSWER` rate before and after counterfactual
- How to aggregate:
  - Report each of 4 primary cells separately
  - Report macro-average over tasks for each target model
  - Report grand macro-average across all 4 cells
  - Also report pooled counts, but do not use pooled significance as the only conclusion
- Valid result vs degenerate run:
  - Valid run requirements:
    - At least 50 usable examples per task after counterfactual filtering
    - Parsing success rate ≥ 95% for target-model outputs
    - Target-model counterfactual change rate ≥ 10% in at least one task; otherwise counterfactuals were too weak
    - Both simulator conditions produce non-constant outputs on at least 2 classes for NLI and at least 5 distinct answers or `NO_ANSWER` for QA
  - Degenerate run indicators:
    - Accuracy exactly 0.0 or 1.0 in any large cell (`N >= 30`)
    - Identical simulator outputs for all examples in a condition
    - Explanation gain near 0 with target-model change rate < 5%, indicating ineffective counterfactual generation rather than null finding
    - More than 10% malformed model responses after one retry

## Implementation Notes
- MultiNLI labels are numeric; map `0->entailment`, `1->neutral`, `2->contradiction`, and drop `-1`.
- SQuAD v2 contexts are long; truncate context to first 1200 characters only if API errors occur, otherwise keep full context for fidelity.
- Use one automatic retry for malformed outputs, but keep the same prompt and `temperature=0.0`.
- Normalize target-model names in file paths, e.g. `gpt-3.5-turbo` → `gpt35`, `gpt-4` → `gpt4`, to avoid awkward filenames.
- Do not compare simulator outputs to dataset gold labels; the target is the target model’s counterfactual output, not task correctness.
- Keep scripts and outputs aligned with the file paths above; avoid introducing alternate experiment scripts or output directories for the primary run.
